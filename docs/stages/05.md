# Stage 5：DeepSeek Harness 源码阅读所需的 TypeScript 模式

## 毕业能力映射

【教学模型】直接服务于：**源码阅读、快速找到真实定义来源**。不讲普通 TS 语法。

## 1. Context module augmentation

【源码事实】DSH Service 经常通过 declaration merging 把 key 加进 Cordis `Context`：

```ts
// 示意；实际定义以 source 为准
declare module '@deepseek-ai/cordis' {
  interface Context {
    tools: ToolRuntime
  }
}
```

【工程解释】看到 `ctx.tools` 不要去找一个巨型 Context class 字段；要找 augmentation + Service/provider registration。

## 2. Merge-extensible Map → union

【源码事实】Session 与 LLM 都大量使用“开放 map，派生 union”：

```ts
interface SessionEventMap { ... }
type SessionEventType = keyof SessionEventMap
type SessionEvent<T extends SessionEventType = SessionEventType> = ...
```

插件可 declaration-merge 新 SessionEvent。

【源码事实】`ContentBlockMap` 也可扩展，然后派生 `ContentBlock`。

### 关键区别

【源码事实】`SessionEventMap` 是 open/extensible，所以处理未知插件 event 的 switch **不应该**用 `assertNever` 强行闭合。

【源码事实】`StreamChunk` 当前是 closed discriminated union，所以 consumer 可以用 `assertNever`，新增 variant 会迫使编译器报出所有未处理点。

这两个相反模式必须能区分。

## 3. Branded ID

【源码事实】仓库用 `Branded<...>` 一类工具把字符串/符号身份变成编译期不可随意混用的 ID，例如 Session/Call/Fs target 等 domain ids。

【工程解释】branded id 是在结构类型系统里补“语义身份”，不是运行时加密或安全边界。

## 4. Event augmentation

【源码事实】Cordis event vocabulary 通过 TS declaration merging 扩展；生成 Event Catalog 能从 declaration 找 dispatcher/listener。

看到：

```ts
ctx.on('agent/request-error', ...)
```

反向导航：

```text
event-producer-consumer.md
→ declaration site
→ payload / mode
→ dispatcher
→ listeners
```

## 5. AsyncIterable + AbortSignal

【源码事实】`LlmAdapter.stream()` 返回 `AsyncIterable<StreamChunk>`；Tool execute、LLM stream、Agent Turn 等关键异步路径都携带 `AbortSignal`。

【工程解释】读这类代码时总问三个问题：

1. 谁创建 signal？
2. 谁只转发 signal？
3. abort 后谁负责等到 quiescence？

只看到 `abort()` 不代表工作已经停止。

## 6. Effect / disposer identity

【源码事实】部分 registry/Agent lifecycle 注释明确要求返回 **exact Cordis effect disposer**，因为 composite effect 的 teardown ordering 依赖 identity。不要习惯性包装：

```ts
const dispose = registry.register(x)
return () => dispose() // 某些 ordered-lifecycle 场景可能改变语义
```

读 JSDoc，确认是否要求 exact disposer。

## 7. Schemastery / Standard Schema

【源码事实】TypeScript `interface Config` 只负责编译期；Loader 用导出的 runtime `Config` schema 验证真实 YAML/`!!js` 值。

## Lab：四次反向追定义

随机选择：

### A. 一个 ctx service

例如 `ctx.sessionPersistence`：从 usage 找 Context augmentation → abstract service → providers → consumers。

### B. 一个 live event

例如 `agent/pre-step`：Catalog → declaration → loop dispatch → listeners。

### C. 一个 SessionEvent

例如 `request/header`：Persistence Catalog / `SessionEventMap` → append producer `buildRequest()` → fold consumer。

### D. 一个 ContentBlock

例如 `tool-call`：`ContentBlockMap` → block interface → stream assembler → Agent Loop tool filtering。
