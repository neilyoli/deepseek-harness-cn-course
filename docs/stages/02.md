# Stage 2：第一个真实 Harness Plugin

## 毕业能力映射

【教学模型】直接服务于：**插件开发、真实安装、Plugin loading 调试**。

## 先写，再系统学 Cordis

【源码事实】官方 first-plugin tutorial 当前支持三种 plugin form：function/module、object、Service class。最常见的是模块导出 `apply(ctx)`，可带 `name`、`inject`、`Config`。

### Lab A：最小 Plugin

在 DSH checkout 根创建：

```text
scratch-plugin/
  src/hello.ts
  patch.yml
```

`src/hello.ts`：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'course-hello'

export function apply(ctx: Context) {
  ctx.logger('course-hello').info('loaded')
}
```

【源码事实】官方基础教程提醒：`--patch` 文件不会改变 Loader 的 module resolution base，所以 scratch source row 使用绝对路径最直接。

`patch.yml`：

```yaml
- insert:
    - id: course-hello
      name: '/ABSOLUTE/PATH/deepseek-harness/scratch-plugin/src/hello.ts'
```

运行：

```bash
pnpm dsh web --patch ./scratch-plugin/patch.yml
```

先 dump，再 boot：

```bash
pnpm dsh web --patch ./scratch-plugin/patch.yml --dump-config
```

### Lab B：增加 Config

【源码事实】Cordis 使用 Standard Schema；DSH/Cordis 教程用 Schemastery。TS interface 与 runtime `Config` schema 是两件事。

```ts
import { Schema as z } from '@deepseek-ai/schemastery'

export interface Config {
  message: string
}

export const Config: z<Config> = z.object({
  message: z.string().default('hello'),
})

export function apply(ctx: Context, config: Config) {
  ctx.logger('course-hello').info(config.message)
}
```

Patch row 改为完整 config：

```yaml
- id: course-hello
  config:
    message: changed
```

### Lab C：inject 一个真实 Harness Service

改为：

```ts
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.logger('course-hello').info(`tool count = ${ctx.tools.schemas().length}`)
}
```

【源码事实】required service 不存在时 `apply()` 不运行，Fiber 处于 PENDING；这是 Cordis dependency lifecycle，不是 JavaScript `undefined` error。

### Lab D：HMR + cleanup

注册一个外部 timer：

```ts
ctx.effect(() => {
  const timer = setInterval(() => ctx.logger('course-hello').debug('tick'), 1000)
  return () => clearInterval(timer)
})
```

编辑 config，观察 unload/reload；确认没有倍增 tick。

### Lab E：移除 Provider

【教学模型】临时 patch 掉提供 `tools` 的 row，观察 course plugin 进入 PENDING / unload；恢复后观察重新 activation。

## Plugin form 边界

【源码事实】当前三种形式：

```ts
// module/function exports
export function apply(ctx: Context) {}

// object
export default { name: 'x', inject: ['tools'], apply(ctx: Context) {} }

// class service
export default class X extends Service {
  static inject = ['tools']
  constructor(ctx: Context) { super(ctx, 'x') }
}
```

【工程解释】如果只是注册 Tool/Hook，function form 通常最清楚；需要提供一个 ctx Service 时 class form 更自然。

## 故障注入

【教学模型】依次制造并记录：

- module path 拼错；
- Config 类型错误；
- `inject=['tools']` 但 provider 不存在；
- `apply()` 主动 throw。

每次只允许用下面四类根因分类：`module resolution / configuration / dependency / plugin apply`。
