# Stage 17：插件工程化与发布

## 毕业能力映射

【教学模型】直接服务于：**发布可复用插件、Real Composition Test、HMR regression**。

## Scratch Plugin 与可安装 Bundle 的差别

【源码事实】官方 publish tutorial 当前把两个 manifest 概念分开：

- **Bundle package**：`package.json#dsh.bundle.patch` 回答“这个包贡献哪层 patch”；
- **Profile directory**：`package.json#dsh.profile.bundles` 回答“这个运行环境按什么顺序装哪些 bundles”。

Bundle 是你发布的；Profile 是用户机器上的 composition。二者不是同一个东西。

dsh-plugin-workspace-reviewer/

## Bundle manifest

【源码事实】发布后的 package 必须让 patch row 用 package name 解析，不能依赖某个源码绝对路径。

```json
{
  "name": "dsh-plugin-workspace-reviewer",
  "version": "0.1.0",
  "type": "module",
  "main": "lib/index.js",
  "files": ["lib", "cordis.patch.yml"],
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
```

### `cordis.patch.yml`

```yaml
- insert:
    - id: workspace-reviewer
      name: dsh-plugin-workspace-reviewer
      config:
        enabled: true
```

`config` 必须按真实 schema 改完整值。

## 安装到真实 Profile

【源码事实】当前 CLI：

```bash
dsh plugin --profile demo add ./dsh-plugin-workspace-reviewer
```

source checkout 使用：

```bash
pnpm dsh plugin --profile demo add ./dsh-plugin-workspace-reviewer
```

验证：

```bash
dsh --profile demo --dump-config
dsh --profile demo
```

remove：

```bash
dsh plugin --profile demo remove dsh-plugin-workspace-reviewer
```

## Git install 的 build-script caveat

【源码事实】`dsh plugin add github:...` 能直接装 git source，但 git dependency 不会自动已有 built `lib`；作者若需要 build，通常提供 `prepare`。pnpm >=10 对 dependency build script 需要 user allowlist，属于在本机安装期执行第三方代码的权限决定。

【工程解释】课程 Capstone 首选本地 tarball 或 npm-style built artifact smoke，避免把“package build permission”误当 Harness loader bug。

## 三层测试

### 1. Unit Test

【教学模型】纯业务逻辑 / schema transformation，不依赖完整 Harness composition。

### 2. Lifecycle / HMR Test

【教学模型】必须证明：

```text
activate
→ tool/service/hook visible
→ dispose Fiber / reload
→ registrations removed
→ re-activate
→ exactly one registration
```

重点不是“dispose 被调用”，而是外部可观察 registry 没有残留。

### 3. Real Composition Test

【教学模型】禁止只做：

```ts
ctx.plugin(plugin)
```

必须至少有一条测试走真实：

```text
profile/bundle patch
→ Loader
→ Cordis tree
→ injections
→ Config
→ ACTIVE
```

可复用仓库的 Loader smoke/test-support；具体 helper 以固定 commit source 为准。

## 发布前 gate

如果插件在 DSH monorepo 内：

【源码事实】官方 adding-package cookbook 推荐相关检查：

```bash
pnpm install
pnpm run doc-sync
pnpm run constraints
pnpm run typecheck
pnpm run lint
pnpm run build
pnpm run hygiene
```

Out-of-tree 插件至少要有自己的：typecheck、tests、build、pack/install smoke。
