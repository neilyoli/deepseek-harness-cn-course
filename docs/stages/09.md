# Stage 9：Agent Loop 非 Happy Path

## 毕业能力映射

【教学模型】直接服务于：**调试排障、Core 修改、理解一致性收敛**。

## 先定义“收敛”

【工程解释】Agent Runtime 出错时真正重要的不是“throw 了什么”，而是：

- open turn/step 是否有合法 close boundary；
- 已经可见/已 durable 的内容是否保留一致；
- started async work 是否达到 quiescence；
- retry ownership 是否唯一；
- abort 后有没有新副作用继续进入；
- 最终 Agent status 是否回到稳定状态。

## Model request failure

【源码事实】`ReactLoopAgent.step()` 用 `BlockAssembler` 消费 stream。adapter 可以 throw，也可以以 terminal error/aborted finish 结束；LLM runtime 把 provider-neutral facts 归一成 `LlmFailure`。

【源码事实】terminal `finish.kind === 'error' | 'aborted'` 时，loop 调用 `agent/request-error` waterfall。若 listener 返回 `{ kind: 'retry' }`，冻结 commit 的 `step()` 当前直接 `continue` 其内部 request loop；否则抛 `LlmError`，由外层 turn catch 形成 error `TurnEndReason`。

::: warning 源码与旧设计说明的冲突
【版本敏感】同一 commit 中，已实现 Agent Note `2026-07-27-request-error-retry-action.md` 的 prose 写着“关闭 failed turn，再打开 retry turn”；但当前 `packages/core/agent-loop/src/agent.ts` 的实际代码是在 `step()` 内 `continue`。本教程按**源码优先**采用后者，并要求你查看当前 tests 进一步固定预期。这个冲突本身就是训练：Implemented Note 解释设计意图，但不能覆盖当前 source behavior。
:::

## Tool failure

【源码事实】Tool pipeline 会把 Tool body / policy / normalization failure 变成 `ToolExecutionResult` error outcome；loop 仍用 `appendToolResult()` 写一个 durable `tool/result`，其 `ToolResultMessage.isError` 为真，并可带稳定 `{name, code}` identity。

【工程解释】Tool error 通常是**模型可见结果**，与“Agent driver 自身崩溃”不同。

## Cancellation

【源码事实】`Agent.cancel()` 会 abort 当前 phase 的 `AbortController`；默认还清 Inbox。`turn()` catch 看到 `signal.aborted` 后把 `turnEnds` 设为 `{kind:'aborted', reason: ...}`，finally 仍尝试 append `turn/end`。

【源码事实】stream 中途 abort：如果 assembler 已有可见 content，loop 可写 `assistant/message { interrupted: true }`，保留已经 delivered 的前缀；未 dispatch 的 tool calls 不会伪装成正常执行。

【源码事实】`tool-calls.ts` 在 abort 后停止补充新 dispatch、等待已 started calls settle，并为未 started 的 model calls 写 synthetic aborted tool result，使 replay 的 call/result 关系保持可解释。

### Fault Lab 3

启动一个尊重 `exec.signal` 的慢 Tool，执行中 `agent.cancel({kind: ...})`。断言：

- signal 到 tool；
- started tool 最终 settle；
- unstarted calls 有 synthetic result；
- `turn/end.reason.kind === 'aborted'`；
- `whenIdle()` 返回后没有 owned work 继续写日志。

## `request-error` recovery ownership

【源码事实】listener 不拥有错误时应该 `next()`；拥有错误时执行 awaited repair，再返回 retry action。多个策略不能用 side channel 争夺 retry。
