# Stage 1：最小 Harness 心智模型

## 毕业能力映射

【教学模型】直接服务于：**架构理解、独立设计**。

## 三层模型

【教学模型】先用这个最小分层理解，注意它不是官方 package 分层：

```text
Application Surface
(Web / Headless / ACP / SDK host ...)
        ↓
Agent Runtime + Capabilities
(Agent, Session, Prompt, LLM, Tools, Persistence, FS ...)
        ↓
Cordis Plugin Runtime
(Context, Service, Fiber, Effect, Events, Loader/Composition)
```

## 为什么普通 `LLM + while + tool calling` 还不是 DSH

【工程解释】最小 while-loop 通常缺少至少这些独立 contract：

- 可组合、可热卸载的插件生命周期；
- swappable provider seam；
- append-only durable Session log；
- live control plane 与 durable data plane 分离；
- agent-scoped registrations；
- policy / hook extension points；
- failure/cancellation/quiescence ownership；
- Profile/Bundle/Patch 的部署 composition。

【源码事实】DSH 的 default loop 只是 `@deepseek-ai/dsh-agent-loop` 一个 plugin；官方架构文档明确说扩展插件依赖 `dsh-agent`，而不是 concrete loop，以保留可替换性。

## “Everything is a Plugin”到底意味着什么

【官方事实】DeepSeek Harness 官方描述为 everything-is-a-plugin，底层由 Cordis 驱动。

【工程解释】这不等于“所有代码都必须是一个 apply 函数”。真正含义是：**运行时能力通过可组合、可逆生命周期挂进 Context / registries / event chains，而不是由一个巨型 Agent class 私有持有全部实现**。

例：

```text
LLM provider     → registerAdapter()
Tool             → ctx.tools.register()
Prompt section   → ctx.systemPrompt.section()
Policy           → waterfall / guard listener
Persistence      → SessionPersistence provider
Filesystem       → FileSystem provider
```

它们都通过 Cordis-managed lifetime 参与系统。

## DSH 与 Cordis 的边界

【源码事实】Cordis 提供 Context / Service / Fiber / Effect / Event / Loader 等通用机制。

【源码事实】`turn/start`、`tool/result`、`LlmAdapter`、`Agent`、`SessionEventMap` 都是 DSH domain，不是 Cordis domain。

【工程解释】所以你修改 DSH 时要先问：

> 这是通用 plugin-runtime 问题，还是 Agent Harness domain contract 问题？

不分边界，就容易把业务策略塞进 Cordis 或把生命周期问题手工绕过 Cordis。

## 反例检查

【教学模型】对以下说法逐一指出错在哪里：

1. “Cordis 就是 Agent Loop。”
2. “Session 就是给 LLM 的 messages。”
3. “Tool 的 timeout 应该每个 Tool 自己 setTimeout。”
4. “想换 remote filesystem 就改 file tool。”
5. “profile 是一份最终 cordis.yml。”

## 验收

【教学模型】向另一名开发者解释：

> DeepSeek Harness 到底是什么？Cordis 又是什么？为什么 Agent Loop 只是 Harness 的一部分？

必须能同时说出 plugin lifecycle、durable session、capability seam、composition 四个关键词背后的具体机制，不只背名词。
