# Stage 16：Capability Seam

## 毕业能力映射

【教学模型】直接服务于：**替换 Provider、架构理解、避免修改 Consumer**。

## Definition / Provider / Consumer

【官方事实】DSH 使用 capability seam 把 contract、implementation 与 consumer 分开。

```text
Service Definition
      ↑ contract
Provider A / Provider B
      ↓ same ctx key
Consumer(s)
```

【工程解释】关键不是“有 interface”，而是：**composition 可以换 provider，consumer dependency graph 不变**。

## 例一：Filesystem

【源码事实】当前四层：

| 层 | Package | 角色 |
|---|---|---|
| Tool | `@deepseek-ai/dsh-tool-fs` | model-facing read/write/edit；调用 `ctx.fs` |
| Policy | `@deepseek-ai/dsh-fs-observation-policy` | read-before-edit / observed state / version guard |
| Definition | `@deepseek-ai/dsh-fs` | `ctx.fs` contract + `fs/*` events |
| Providers | `dsh-fs-local`, `fs-sandbox`, `fs-e2b` | host / sandbox / remote execution-world storage |

【工程解释】file Tool 不应该知道 Local/E2B/Sandbox，因为它拥有的是 model UX 与 windowing，不是 storage mechanism。

## 例二：Shell（本阶段 Lab 选它）

【源码事实】当前：

```text
@deepseek-ai/dsh-shell        Definition: ShellExecutor / ctx.shell
@deepseek-ai/dsh-bash-local   Provider
@deepseek-ai/dsh-bash-sandbox Provider
@deepseek-ai/dsh-tool-bash    Consumer
```

`ShellExecutor` abstract methods：

```ts
abstract resolve(request: ShellExecRequest): ShellExecSpec
abstract run(spec: ShellExecSpec): Promise<ShellRunResult>
abstract start(spec: ShellExecSpec): ShellProcess
```

构造器 `super(ctx, 'shell')`，所以一个 Context 里装两个 provider 会触发标准 duplicate service failure。

## Contract 细节比方法签名更重要

【源码事实】`run()` **只在基础设施错误时 reject**；nonzero exit、timeout kill、abort kill 都应 resolve 成描述性 `ShellRunResult`。

【源码事实】`start()` 立即返回 `ShellProcess`，后台进程没有 foreground timeout；owned teardown 必须最终 kill/await live processes。

【工程解释】如果 mock provider 在 exit code 1 时 throw，它虽然 TypeScript 签名兼容，却违反 behavioral seam。

## Lab：Mock Shell Provider

【教学模型】实现 `CourseShell extends ShellExecutor`：

- `resolve()` 给默认 workdir/timeout/output cap；
- `run()` 只识别固定命令 `course:ok`, `course:fail`, `course:slow`；
- `course:fail` 返回 nonzero result，不 throw；
- `course:slow` honor signal；
- `start()` 返回 deterministic in-memory `ShellProcess`。

然后通过 composition **替换** local provider row，保持 `@deepseek-ai/dsh-tool-bash` 不动。

验收命令要覆盖：

```text
Tool schema 仍存在
bash Tool 调用进入 CourseShell
nonzero exit 仍是 normal ShellRunResult
abort 能收敛
恢复原 provider 后 Consumer 无修改继续工作
```

## Provider replacement 的调试顺序

```text
capability-seams.md 找 Definition/Provider/Consumer
↓
读 Definition README（behavioral contract）
↓
读至少两个 Provider 比较共同点
↓
读 Consumer 只确认它依赖 definition
↓
用 Profile/Patch 替换 Provider row
↓
run shared contract tests / real composition
```
