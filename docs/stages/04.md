# Stage 4：DeepSeek Harness 如何启动

## 毕业能力映射

【教学模型】直接服务于：**源码阅读、Plugin loading 调试、Profile/Bundle/Patch 理解**。

## 当前真实纵向链

【源码事实】固定 commit 的主线：

```text
apps/cli/src/bin.ts
  ↓ parseDshArgs()
apps/cli/src/profile-boot.ts::runProfile()
  ↓ composeProfile()
packages/boot/app-boot/src/profile.ts
  ↓ loadProfile() / composeEntries()
packages/boot/app-boot/src/index.ts::boot()
  ↓ new Context()
  ↓ ctx.plugin(Loader)
  ↓ mountRootInclude()
  ↓ loader.create(root include)
  ↓ loader.await()
  ↓ assertEntriesActivated()
Cordis Plugin Tree settled
```

## CLI：launcher 只拥有自己的 flags

【源码事实】`apps/cli/src/args.ts` 只解析：profile、`--patch`、dump、plugin subcommand；第一个 launcher 不认识的参数以后交给 booted app。例如：

```bash
dsh --profile tui --resume abc
```

`--resume abc` 属于 app，而不是 launcher。

## Profile 与 Bundle resolution

【源码事实】`loadProfile()` 读取 profile manifest 的 `dsh.profile.bundles`，按顺序解析 bundle package 的 `dsh.bundle.patch`。

【源码事实】profile 首次由 `dsh plugin` 管理时会以 `@deepseek-ai/dsh-base` 初始化；Web/Headless 内置模板也把 base 放首层。

## Precedence

```text
bundle 1
bundle 2
...
profile cordis.patch.yml
home cordis.patch.yml
--patch #1
--patch #2
...
launcher-owned overlays (when applicable)
```

【源码事实】row config 的 patch 是 whole replacement，不是 deep merge。

### Lab：亲自证明 replacement

1. dump 一个有至少 2 个 config key 的 row。
2. 新建 patch，只写其中 1 个 key。
3. 再 dump。
4. 证明其他 key 消失。
5. 恢复时写完整 config。

## `boot()` 的失败分类

【源码事实】`boot()` 在 host prepare 后切换 failure stage 为 `plugin tree failed to load`；异常时先 dispose partial context，再把 deepest cause stack 拼回 diagnostic。

【源码事实】`assertEntriesLoaded()`：enabled row 没有 Fiber → module 无法加载。

【源码事实】`assertEntriesActivated()`：

- ACTIVE → OK；
- FAILED → await fiber 得到原始 activation error；
- PENDING → 枚举 `fiber.inject` 中 Context 缺失的 service，报告 `waiting for service(s)`。

## Lab：四种“我的 Plugin 为什么没有启动”

### Case 1 module resolution

把 `name` 写成不存在 module。找 Loader error 与 `assertEntriesLoaded` 的最终诊断。

### Case 2 configuration

给 Schemastery Config 传错类型。找到 Config validation 的 activation failure。

### Case 3 dependency

保留有效 module/config，但声明不存在 Service；观察 PENDING 和 missing service 名称。

### Case 4 plugin apply

`apply()` 中 throw `new Error('lab-apply')`；确认 deepest stack 能指回你的 source。

## HMR user patches

【源码事实】`runProfile()` 会 watch profile patch 与 home patch。重新 compose 时始终重新读取两份 user files，并把 bundle 放下、overlays 放上，防止某次热更新把 stale layer 固化。
